# 프로젝트 케이스 스터디 재설계

## 목표

프로젝트 상세 페이지를 실제 제품 화면과 검증 가능한 기술 근거가 중심인 케이스 스터디로 재구성한다. 사용자는 첫 화면에서 결과물을 확인하고, 이어지는 사용자 흐름·아키텍처·기술 의사결정·문제 해결 기록을 통해 구현 범위와 기여도를 판단할 수 있어야 한다.

## 문제 정의

- Kagoshima Travel은 현재 추상적인 `architecture.svg`를 대표 이미지와 본문에서 반복하고 실제 서비스 화면 갤러리가 비어 있다.
- Cledyu의 코드형 아키텍처는 구조를 설명하지만 실제 참고 이미지를 바탕으로 정리한 아키텍처 결과물보다 정보 밀도와 설득력이 낮다.
- 기술 로고가 역할 설명 없이 나열되어 구현 역량보다 템플릿처럼 보인다.
- 모든 프로젝트가 같은 카드 구조를 반복해 프로젝트별 특성과 작업 과정이 충분히 드러나지 않는다.

## 디자인 원칙

1. 실제 화면을 가장 먼저 보여준다. 합성 목업보다 운영 화면과 직접 촬영한 자료를 우선한다.
2. 이미지는 장식이 아니라 근거로 사용한다. 각 이미지에는 무엇을 구현했고 사용자가 어떤 행동을 수행하는지 설명한다.
3. 아키텍처는 실제 배포 구조만 표시한다. 계획 단계의 기술이나 확인되지 않은 연결은 넣지 않는다.
4. 기술 스택은 `기술명 + 담당 역할`로 표현한다. 로고만 나열하지 않는다.
5. 짧은 제목, 구체적인 본문, 충분한 여백으로 읽는 순서를 명확하게 만든다.
6. Kagoshima Travel은 `개선 진행 중` 상태를 명시하고 현재 제공되는 기능과 다음 개선 범위를 구분한다.

## 페이지 구조

### 프로젝트 히어로

- 프로젝트명, 한 문장 설명, 상태, 기간, 역할, GitHub와 운영 서비스 링크를 표시한다.
- 대표 이미지는 실제 제품 화면을 사용한다.
- Kagoshima Travel은 운영 중인 서비스이면서 UI 개선 중임을 별도 상태로 표시한다.

### 프로젝트 개요

- 문제, 해결 방향, 담당 범위를 3개 요약 블록으로 제시한다.
- 담당 범위는 Frontend, Backend, Cloud Infrastructure를 구분하되 하나의 사용자 흐름으로 연결해 설명한다.

### 사용자 흐름과 실제 화면

- Kagoshima Travel은 `장소 저장 → 일정 구성 → 오늘 일정 확인 → 지도 길찾기 → 읽기 전용 공유` 순서로 구성한다.
- Cledyu는 `Lab 탐색 → VM 프로비저닝 → 브라우저 터미널 → 단계 검증 → 학습 현황` 순서로 구성한다.
- 데스크톱과 모바일 화면을 섞되 동일 화면의 중복 캡처는 피한다.

### 실제 아키텍처

- Cledyu는 기존에 실제 참고 이미지를 바탕으로 제작한 아키텍처 이미지를 사용한다.
- Kagoshima Travel은 Vercel React PWA, OCI VM의 Caddy와 Go API, Supabase PostgreSQL, Google Places/Maps의 실제 운영 연결을 새 아키텍처로 표현한다.
- 아키텍처 이미지 아래에는 요청, 데이터, 외부 API, 배포·복구의 흐름을 짧게 설명한다.

### 기술 역할

- 기술 로고를 일관된 크기의 타일로 표시하되 로고 아래에 실제 역할을 함께 적는다.
- 예: `Go — 인증·여행 도메인 REST API`, `Caddy — TLS 종료와 API reverse proxy`.
- CSS로 만든 가짜 로고나 의미 없는 플레이스홀더는 사용하지 않는다.

### 문제 해결과 결과

- 문제, 원인, 조치, 확인 결과의 순서를 유지한다.
- 일반적인 설명보다 실제 운영 과정에서 확인된 인증, API 호출량, 배포 복구, 권한 경계 문제를 우선한다.

## 프로젝트별 적용

### Kagoshima Travel

- 실제 사이트와 제공받은 관리 화면을 대표 근거로 사용한다.
- 운영 사이트 링크 `https://kagoshima.hjh-dev.site/`를 추가한다.
- 모바일 우선 여행 플래너, HttpOnly 세션, 읽기 전용 공유, Places 월 사용량 보호, PWA 오프라인 복구를 핵심 구현으로 설명한다.
- 프로젝트 상태는 `운영 중 · 화면 개선 진행 중`으로 표시한다.

### Cledyu

- 실제 서비스 화면과 정리된 서비스 아키텍처 이미지를 함께 사용한다.
- 사용자 요청, 인증, Lab 세션, 검증 이벤트, 오버플로·DR 흐름이 아키텍처에서 읽히도록 한다.
- 세부 기술은 서비스 흐름과 Platform Control Plane으로 분리해 과도한 선 교차를 피한다.

## 반응형과 접근성

- 이미지에는 화면 기능을 설명하는 구체적인 대체 텍스트를 제공한다.
- 작은 화면에서는 2열·3열 구성을 1열로 전환하고 본문이 이미지보다 먼저 잘리지 않게 한다.
- 외부 링크는 텍스트만으로 목적을 알 수 있게 하고 키보드 포커스를 유지한다.
- `prefers-reduced-motion` 환경에서는 등장 애니메이션을 생략한다.

## 검증 기준

- 프로젝트 상세 페이지 테스트에서 상태, 운영 링크, 실제 이미지, 아키텍처 섹션, 기술 역할이 렌더링되는지 확인한다.
- `npm test`, `npm run lint`, `npm run build`를 실행한다.
- 데스크톱과 모바일 너비에서 대표 이미지, 갤러리, 아키텍처, 링크의 잘림과 가로 넘침을 시각 검증한다.
